# 部署上线与交付

## 站点是纯静态的

`assets/site/` 不需要构建、不需要 Node、不需要数据库，可直接用静态服务器托管：

```bash
python -m http.server 8766 --directory assets/site
```

必须包含 `index.html`、`styles.css`、`app.js`、`pack.js`、`runtime.js`、`export.js` 与 `assets/`（含 `assets/pet/`）。`download/wangzai-pet-exe.zip` 可选，约 17 MB。

## 用 WorkBuddy 发布应用

1. 确认所有文件**已写到磁盘**。
2. 调用发布工具，`directory` 指向站点目录，`language: "static"`，提供 `appName` 与 `domainPrefix`。
3. 首次发布创建新应用，之后同目录发布**覆盖同一条链接**。
4. 工具返回 `shareLink`（形如 `https://<domain>/?sharecode=<code>`）与 `verified`。
5. 管理入口：**「设置—数据管理—应用」**。

用户在本轮明确说「上线 / 发布 / 要链接」时才设置发布许可；之后每次改动要重新征求。

## 分享码与 Cookie

带 `?sharecode=<code>` 的首次访问会写入 `__wb_rsc` 会话 Cookie；之后同域的 `app.js`、PNG、下载 zip 都依赖这个 Cookie。用 curl 验证时记得带 cookie jar：

```bash
curl -c jar -L "https://<host>/?sharecode=<code>" -o /dev/null
curl -b jar -L -o /dev/null -w "%{http_code}\n" "https://<host>/app.js"
curl -b jar -L -o /dev/null -w "%{http_code}\n" "https://<host>/download/wangzai-pet-exe.zip"
```

不带 Cookie 的裸请求会返回 403，这是平台的访问控制，不是站点故障；真实浏览器首次带码访问后一切正常。

## 网页发布 ≠ 小程序发布

- 网页发布产出的是 **HTTP 链接**；小程序是另一套 WXML/WXSS/JS 代码，不能由 HTML 转换而来，也不能靠微信开发者工具「打开网页」实现。
- 小程序要走独立的应用空间：创建 / 复用小程序应用 → 预览面板右上角「分享 / Share」→ 绑定账号（试用小程序无需 AppID）→ 上传、提审、发布。
- 因此本仓库同时提供 `web/`（网页链接）与 `miniprogram/`（小程序工程）两套代码，用 `config.js` 的链接打通。

## 自己托管 / GitHub Pages

- 站点是纯静态，可直接推到 GitHub Pages、对象存储或任意 CDN。
- 若自建托管没有分享码，把 `app.js` / `config.js` 里的 `sharecode` 参数去掉即可；网页本身不依赖它。
- 生成 EXE 下载包：`python scripts/build_exe.py --out <site>/download/wangzai-pet-exe.zip`。
